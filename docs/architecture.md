# Coach23 技术架构

版本：v0.1 · 更新日期：2026-10-01。

## 1. 架构目标

目标链路为：数据源适配器 → Athlete DB → Athlete Engine → Coach Context → CoachAgent → 评审草稿 → 用户确认与计划执行。

长期数据与计算能力由应用后端维护，教练推理通过可替换接口调用。目标部署在云端，不依赖用户电脑持续在线。当前仅实现本地模拟链路。

## 2. 当前运行方式

使用 Node.js 22+ 标准库，不依赖第三方运行包。HTTP 服务监听本机回环地址，提供 API 和中文调试页面。数据存储在内存，重启即清空。当前无用户登录功能，不应直接公开部署。

## 3. 模块边界

| 模块 | 当前职责 | 待实现能力 |
| --- | --- | --- |
| `packages/integrations` | 统一异步同步接口；Strava、WHOOP 返回模拟数据，Suunto 返回空记录 | OAuth、分页、刷新令牌、限流、重试和删除同步 |
| `packages/athlete-db` | 内存记录存取，按运动员隔离查询 | 云端持久化、事务与同步状态 |
| `packages/athlete-engine` | 汇总七日运动时长、读取当日恢复指标 | 个人基线、训练负荷与恢复趋势 |
| `packages/context-builder` | 生成版本化上下文并标注数据限制 | 比赛目标、当前计划和相关历史决策 |
| `packages/coach-engine` | 可注入的教练接口与固定规则演示 | 真实模型调用、结构化输出校验 |
| `jobs/daily-review` | 编排模拟同步、计算与评审，可由命令执行 | 云端调度、任务持久化与失败恢复 |
| `apps/api`、`apps/web` | 本地 API 与调试界面 | 身份认证、正式计划与审批交互 |

调用实时适配器模式会明确报错，不会静默返回模拟数据。当前教练不会调用模型、改变计划或发送通知。

## 4. 数据流与接口约定

适配器的 `sync({ athleteId, now })` 返回标准化记录。记录包含运动员标识、平台、平台记录 ID、记录类型、日期和对应指标。

内存仓库以“运动员 + 平台 + 记录类型 + 平台记录 ID”为唯一键，重复同步覆盖同一记录。跨平台导入的同一次训练尚未合并，生产实现需单独处理。

Athlete Engine 使用含今天在内的七个 UTC 日历日，排除窗口外记录和无效运动时长。当日恢复分缺失时返回空值，不复用旧日恢复分。HRV 基线当前为空，不能据此生成真实训练建议。后续应使用运动员本地时区。

Coach Context 携带版本号、运动员标识、计算状态和限制。CoachAgent 的 `review(context)` 返回建议草稿。生产实现应在保存和执行前校验输出结构、关联数据及计划版本。

## 5. 数据库草案

迁移文件：`supabase/migrations/202610010001_initial.sql`。

| 表 | 用途 | 当前约束 |
| --- | --- | --- |
| `athletes` | 运动员资料与时区 | ID 关联认证用户 |
| `source_records` | 数据源记录及原始载荷 | 按运动员、平台、类型、外部 ID 唯一 |
| `coach_reviews` | 评审日期、上下文、建议和状态 | 每个运动员每日一条评审 |

三张表均启用行级安全策略，仅为认证用户开放本人数据的读取；写入预期由可信后端完成。服务端必须验证调用身份，不能直接信任客户端传入的运动员 ID。

迁移尚未应用或进行数据库集成测试。当前表结构不包含 OAuth 令牌、完整训练计划、通知队列或评审版本历史。每日评审唯一约束在支持多次修订前需要重新设计。

## 6. 生产接入要求

1. 确认部署方案与凭据存储，实现身份认证和数据库仓库，验证跨用户访问被拒绝。
2. 实现 Strava / WHOOP OAuth 状态校验、令牌加密与刷新并发控制、分页同步、限流处理和事件通知校验；实时接入前核对官方接口。
3. 保留数据来源与更新时间，处理历史回填、跨来源去重、删除和时区转换。
4. 接入一个真实 CoachAgent 实现，校验结构化输出，持久化建议与确认记录。
5. 加入每日、每周和训练后任务，以及幂等处理、失败重试、任务监控和通知去重。

模型或 Agent 平台通过接口替换。此前讨论的 Dot 仅是候选实现，具体可用接口尚待验证。MCP 可作为后续工具接入方式，不是核心数据链路的前置依赖。

## 7. 配置与验证

密钥仅保留在服务端，不存入当前公开业务表或提交到 Git。`.env.example` 是配置占位；当前仅读取进程中的 `PORT`，不会自动加载 `.env`。

`npm test` 覆盖重复同步、运动员隔离、无效值与时间窗口、实时适配器边界及 HTTP API。`npm run check` 检查 JavaScript 语法。数据库权限、真实平台连接与模型输出仍需独立验证。
