# Coach23 产品需求文档（PRD）

版本：v0.1 · 更新日期：2026-10-01 · 状态：MVP 规划，开发骨架已完成。

## 1. 产品定位

Coach23 是面向耐力运动员的 AI 教练。通过持续汇聚训练与身体恢复数据，维护运动员档案，围绕比赛目标制定计划，并在训练后复盘、调整和主动提醒。

首个验证场景是以 11 月 14 日百公里越野跑为目标的个人备赛。日期作为用户目标配置，不写死在系统中。力量训练是计划中的一级对象，需要与跑步、恢复和比赛周期共同安排。

## 2. 用户问题与成功标准

运动记录、恢复状态和计划分散在不同平台，用户需要自行判断当天是否适合训练、偏离计划后如何处理，以及力量训练何时安排。

MVP 的成功标准是形成可追溯的闭环：真实数据持续入库 → 根据个人目标与近期状态生成建议 → 用户确认调整 → 记录执行情况 → 下一次评审能够使用这些结果。不能用演示数据流程成功代替真实闭环验收。

## 3. 核心用户旅程

1. 用户设置比赛目标、可训练时间和已有训练安排，授权数据源。
2. 系统同步历史与最新记录，展示数据来源、更新时间及缺失状态。
3. 系统形成初始运动员档案与训练计划，用户确认后执行。
4. 每日评审结合恢复数据、近期训练和原计划，提出有依据的建议。
5. 训练后比较计划与实际完成情况，记录偏差与用户反馈。
6. 必要时提出未来训练调整，用户确认后生成新版本。
7. 每周回顾执行与恢复趋势，更新下一阶段安排。

## 4. 功能需求

| 功能 | MVP 要求 | 验收依据 |
| --- | --- | --- |
| 数据接入 | 优先接入 Strava、WHOOP；Suunto 独立适配 | 能查询同步状态，重复同步不重复入库，失败可重试 |
| 运动员档案 | 保存目标、训练记录、恢复状态和个人基线 | 指标有时间范围和来源，缺失值不被伪装为正常值 |
| 训练计划 | 同时支持耐力、强度、力量、休息安排 | 可查看当天任务、计划版本和执行状态 |
| 每日评审 | 根据当日可用数据与计划提出建议 | 输出理由、数据限制及建议变更；缺少关键数据时明确说明 |
| 训练后复盘 | 比较实际训练与原定任务 | 能记录偏差和反馈，并用于后续评审 |
| 计划调整 | 保留原计划、建议和确认记录 | 未确认的建议不覆盖生效计划 |
| 主动提醒 | 由定时任务或训练事件触发 | 可追踪触发与发送结果，避免相同事件重复通知 |
| 每周回顾 | 汇总执行情况和恢复趋势 | 能查看总结及下一阶段建议 |

Suunto 实际接入需先确认权限，不阻塞 Strava + WHOOP 主流程。力量训练动作、组次和负荷的详细数据结构将在计划模块实现时细化。

## 5. 产品原则

- 长期历史保存在数据库，模型接收必要的上下文摘要和相关记录。
- 计算指标与教练推理分开，建议能追溯到数据和计划版本。
- 数据缺失、过期和跨平台重复记录必须显式处理。
- 第一阶段计划变更由用户确认，自动化执行权限后续单独定义。
- 云端部署后不要求个人 Mac 持续开机。

## 6. 当前已实现与未实现

已实现本地调试页面、Strava / WHOOP 模拟记录、Suunto 空适配器、内存仓库、七日运动时长计算、版本化教练上下文和规则演示评审。

尚未实现真实授权同步、持久化数据库连接、个人基线与训练负荷计算、真实 AI 推理、训练计划、计划确认、定时调度和通知。当前恢复分与 HRV 为模拟数据，运动时长不等于训练负荷。

## 7. 交付顺序

1. 数据库与身份认证：验证用户隔离和持久化。
2. 真实同步：完成 Strava、WHOOP 授权与增量同步；确认 Suunto 权限。
3. 状态计算：处理来源去重、个人时区和历史基线。
4. 教练与计划：接入可替换的教练实现，保存计划和评审版本。
5. 主动工作流：部署每日、每周和训练后任务及通知。

首版不要求完整手机 App、复杂可视化前端或专用 Mac mini。部署平台、模型提供方、通知渠道、数据保留周期和比赛具体信息仍需在对应阶段确认。
